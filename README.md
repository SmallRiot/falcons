# 🦅 Falcons — Telegram Mini App хоккейной команды

Запись на лёд, пятёрки, взносы, заточка коньков и бот, который обо всём напоминает.

## Что умеет

| Кто | Что |
|---|---|
| **Игрок** | Записывается на тренировки и игры («Иду / Не иду» — прямо в приложении или кнопкой в чате), видит свою пятёрку, выбирает вариант взноса, платит в пару тапов (копирование ФИО/IBAN/суммы/назначения) и прикрепляет скрин, заказывает заточку, смотрит свою статистику |
| **Тренер** | Создаёт события (бот сразу постит их в чат), расставляет пятёрки: «Тёмные / Светлые» или одна команда, авторасстановка по позициям, тап-тап-перестановка. После публикации каждый игрок получает личное сообщение вида «Ты сегодня во второй пятёрке тёмных…» |
| **Админ** | Пускает людей в приложение (кнопки прямо в Telegram), раздаёт роли, проводит взносы: опрос → «Начать сбор» → проверка скринов, закрывает запись должникам, ведёт счета |
| **Сервис-менеджер** | Очередь заточки: проверяет оплату, «в работе» → «готово», записывает долг любому игроку |

### Два приложения в одном дизайне
| | Для кого | Dev | Прод |
|---|---|---|---|
| **Мини-приложение** (`web/`) | игроки, в Telegram, мобильное | http://localhost:5180 | `PORT` (8787) |
| **Веб-консоль** (`console/`) | админы и тренер, десктоп, вход через Telegram | http://localhost:5181 | `CONSOLE_PORT` (8788) |

Общий дизайн, компоненты, API-клиент и логика пятёрок — в `shared/`. Сервер один: отдаёт API на обоих портах, база и бот общие. В консоль пускает только админа и тренера; игрок увидит «Нет доступа».

**Консоль:**
- **Обзор** — KPI, ближайшие события со статусом пятёрок, заявки на доступ (пустить в один клик), взносы месяца, должники, кто реже всех ходит;
- **Расписание и пятёрки** — таблица событий, создание/правка в боковой шторке, счёт игр, отмена; **доска пятёрок**: пул записавшихся слева, тёмные/светлые справа, перетаскивание мышкой, авто по позициям, подсветка «не своей» позиции, предпросмотр картинки площадки, которая уйдёт в чат;
- **Игроки** — составы и роли переключаются в строке, посещаемость за 30 дней, долг, закрыть запись, заявки;
- **Посещаемость игр** и **Стата тренировок** — матрицы с отметкой «был/не был» кликом;
- **Финансы** — новый месяц (опрос), «Начать сбор», KPI, фильтры, проверка скринов, список должников (скопировать или таблицей в чат), напоминания;
- **Заточка** — очередь и должники, «записать долг»; **Составы**; **Счета**.

Один человек может быть сразу игроком и админом/тренером. В мини-приложении у админа, тренера и сервиса сверху справа переключатель «Игрок / Админка». По умолчанию они открывают приложение сразу в «Управлении» — нижние кнопки ведут в админку (Обзор, События, Люди, Взносы, Заточка). Выбор запоминается; ссылка от бота на админский экран включает управление сама.

### Составы
В клубе несколько составов (сейчас: один первого дивизиона и два второго — названия, метки и цвета правятся в «Профиль → Составы»). Игрок может играть сразу за несколько. **Тренировки общие** — их видят все. **Игры — у каждого состава свои**: игрок видит и получает напоминания только по играм своих составов, записаться на чужую игру нельзя. Тренер и админ видят все игры, фильтруют по составу.

### Взносы
1. Админ создаёт месяц и сам указывает, сколько собираем (бюджет), → в чат летит **опрос без сумм** (Полный / Частичный 70% / Донат 100 ₾). Выбор прошлого месяца переносится.
2. Когда все выбрали — **«Начать сбор»**: бюджет делится на всех (`бюджет = Nполн·F + Nчаст·0.7F + донаты`, округление вверх до 5 ₾), суммы фиксируются, каждому в личку — его сумма, в чат — пост «Сбор открыт».
3. Игрок переводит, прикрепляет скрин → админ жмёт «Деньги пришли» или «Отклонить» (с причиной).
4. Игроки бюджет не видят — только расклад голосов и свою сумму после старта сбора.
5. Неоплата = долг: окно при каждом входе в приложение, напоминание от бота раз в ~2,5 дня, по кнопке админ закрывает запись на тренировки.

### Пуши от бота
- новое событие → пост в командный чат с кнопками «✅ Иду / ❌ Не иду» (счётчик в посте обновляется сам);
- пятёрки опубликованы → пост в чат + личное сообщение каждому, где он играет (при правке — только тем, у кого что-то поменялось);
- завтра событие, а ты не отметился → личное сообщение с кнопками «Иду / Не иду»;
- долг по взносам / за заточку / не выбран вариант → напоминание раз в 60 ч (настройка `remind_every_hours`), только с 10:00 до 22:00 по Тбилиси;
- оплата принята / отклонена, заточка принята / готова / долг, доступ открыт, запись закрыта.

Главные сообщения бот шлёт как **Rich Messages** (Bot API 10.1+): заголовки и таблицы — пост тренировки со списком идущих (обновляется сам), пятёрки таблицей «ЛН · ЦН · ПН · ЛЗ · ПЗ» по тёмным/светлым, личное «твоё звено» со ⭐, опрос и старт сбора с таблицей вариантов, твоя сумма, напоминание о долге, таблица должников из консоли («Отправить в чат таблицей»). Если Telegram не примет rich-сообщение, бот сам пошлёт обычный текст из тех же данных.

**Заявка:** достаточно нажать /start у бота — человек попадает в «Заявки», админу приходит сообщение с кнопками «Пустить / Отклонить», а бот после этого может писать ему в личку.
**Новичок:** после одобрения при первом входе выпадает анкета — имя, фамилия, дата рождения (+ номер и позиция); пока не заполнит, дальше не пустит.
**Дни рождения:** утром (после 10:00 по Тбилиси) бот шлёт в командный чат открытку «С днём рождения» с именем и номером, имениннику — личное поздравление. 29.02 в невисокосный год — 28-го. В консоли: ближайшие ДР в «Обзоре», колонка «ДР» в «Игроках».

Все личные сообщения дублируются в ленту 🔔 в приложении — это удобно для теста без бота.

> **Счета:** только ФИО получателя и IBAN — банк приложение определяет по IBAN само (GE00 **TB**… → TBC, **BG** → Bank of Georgia, **LB** → Liberty). У игрока в оплате — копирование ФИО, IBAN, суммы и назначения в один тап и кнопка «Всё». Админ свою оплату может отметить без скрина.

## Стек

- **server/** — Node 24 (TypeScript запускается без сборки), Fastify, встроенный `node:sqlite`. Без внешней БД.
- **web/** — React 18 + Vite, тема подстраивается под светлую/тёмную тему Telegram.
- Бот — обычный Bot API через `fetch` (long polling), без лишних библиотек.

## Запуск локально (тест в браузере)

```bash
npm install
cp .env.example .env      # DEV_AUTH=1 уже включён
npm run seed              # демо-данные: 20 игроков, события, взносы, заточка
npm run dev               # API :8787 + мини-приложение :5180 + консоль :5181
```

Открой http://localhost:5180 и выбери, под кем зайти: `1` админ, `2` тренер, `3` сервис, `4–20` игроки, `21` ждёт доступа. Переключиться можно кнопкой в правом верхнем углу. Без `BOT_TOKEN` сообщения бота печатаются в консоль сервера и попадают в ленту 🔔.

Пересоздать демо-базу: `npm run seed -- --force`.

## Подключение к Telegram

1. @BotFather → `/newbot` → токен в `BOT_TOKEN` (`BOT_USERNAME` можно не заполнять — сервер узнает его сам).
2. Задеплоить на https-адрес (Mini App работает только по https) → `WEBAPP_URL`.
3. @BotFather → `/newapp` → указать `WEBAPP_URL`, придумать short name → `APP_SHORT_NAME`. Тогда ссылки из бота открывают нужный экран (`?startapp=e12`, `finance`, …).
4. Добавить бота в командную группу (он сам поздоровается и позовёт всех нажать /start). Админ пишет в нужных топиках: `/here_trainings` — тренировки, `/here_games` — игры, `/here_dues` — взносы и должники, `/here_general` — поздравления с ДР и общее (туда же всё, для чего свой топик не задан). Бот запоминает группу и топики сам (без правки .env). `/chatid` покажет номера.
5. Для **веб-версии** (вход «Войти через Telegram» на сайте): @BotFather → `/setdomain` → домен сайта. Вход выдаёт сессию на 30 дней (ключ — `SESSION_SECRET` или сгенерированный `DATA_DIR/session.key`). Аккаунт и роли те же, что в мини-приложении: игрок-админ видит и свои экраны, и админку.
6. Свой Telegram id → `ADMIN_IDS` (первых админов пускает сразу, остальных одобряют они).
7. **Тестовый режим:** `TEST_CHAT_ID=<твой id>` — все сообщения бота (и личные, и в командный чат) приходят тебе с пометкой «кому». Автонапоминания в этом режиме — не больше 5 за прогон. В проде оставить пустым.
8. **`DEV_AUTH=0`** в проде — иначе любой сможет войти под кем угодно.

Прод: `npm run build && npm start` — сервер отдаёт и API, и собранный фронт на одном порту. Данные лежат в `DATA_DIR` (база + скрины) — эту папку и надо бэкапить.


собирает Docker-образ → останавливает старую версию → бэкапит базу в `/opt/falcons/backups` → запускает новую →
проверяет `/healthz`; если не поднялась — откатывает на предыдущий тег.

Сервер (31.57.13.187, рядом живут другие сайты):
- контейнер `falcons` слушает только `127.0.0.1:8787` (мини-приложение + API) и `127.0.0.1:8788` (консоль);
- nginx: `/etc/nginx/sites-available/appka.gihl.ge` + `snippets/falcons-app.conf` (копии — в `deploy/`), `/console/` → 8788, остальное → 8787;
- HTTPS: Cloudflare + сертификат Let's Encrypt на сервере (продлевается сам, nginx перезагружается хуком);
- данные: `/opt/falcons/data` (база + фото + скрины), настройки: `/opt/falcons/.env` (DEV_AUTH=0);
- выкладывает пользователь `falcons`, его SSH-ключ (секрет `DEPLOY_SSH_KEY` в GitHub) умеет только запускать `deploy.sh`.

Посмотреть, что крутится: `ssh root@31.57.13.187 'cat /opt/falcons/current; docker ps --filter name=falcons'`.

## Безопасность

- Вход только по подписанному `initData` от Telegram (HMAC с токеном бота), новый пользователь попадает в «ожидают доступа».
- Скрины оплат отдаются только владельцу, админам и (для заточки) сервис-менеджеру.
